# 节点式自动化引擎 —— 架构与开发指南

本项目正从"写死的出农脚本"重构为**节点式可视化自动化引擎**：把"检测 → 判断 → 操作"
的流程拆成可在画布上自由连线的节点图，以支持出农、市场出商队、金朝双出农等多种场景，
未来新需求多数只需改连线/改参数，少数加一个小节点即可。

> 旧的 `main.py` / `gui_app.py` / 各 `*_reader.py` 暂保留，其算法作为节点内部实现被复用，
> 待编辑器成熟后再行清理。

## 1. 执行模型：执行流 + 数据流（类 Blueprint）

- **执行流（exec）**：白色实线，决定"先做什么、再做什么"。入口是 `event.on_tick`，
  沿执行线逐个访问控制节点。「分支」(`control.if`) 等节点有多个执行出口（如 真/假），以此实现分支
  与"跳过本轮"；出口不接任何节点即"本帧到此结束"（无专门的结束节点）。
- **数据流（data）**：彩色线，**惰性传值**。当某节点需要一个输入值时，才向上游"拉取"，
  且结果**按帧记忆化**（同一帧内每个节点输出只算一次）。
- 一帧（tick）结束后，执行器**兜底释放**可能持有的输入屏蔽与文件锁，避免跨帧泄漏。

与旧主循环的对应：`修饰键暂停 → 窗口检测 → 队列检测(不满足则跳过本轮) → OCR → 条件 → 操作`
逐条映射为节点与执行线分支。

### 性能要点

- **按帧、按区域懒加载截图**：某区域本帧第一次被需要时才截，之后同帧同区域直接命中缓存复用
  （见 `ExecutionContext.capture_region`）。识别区都很小、合计约占屏 1%，逐区域按需截通常最省。
- `整屏预取`（`control.prefetch_full`）**默认不用**：Windows 下每次截屏都有约 8ms 的 DWM 同步固定开销，
  整屏还要多拷一整块位图（2560×1440 实测约 62ms）。只有当一帧要读很多个不同区域、累计截图次数多于
  整屏一次时才划算。保留它仅为兼容老流程/特殊场景。
- 重型识别（OCR）只在被取到的执行路径**实际需要时**才求值；扇出给多个下游也只算一次（按帧记忆化）。
- 保留旧的微优化：`GetPixel` 取像素（<0.1ms，绕过截图）、灰度模板匹配、模板缓存、
  `control.every` 定时门限频。
- 截图实例（mss）随**单条常驻引擎线程**复用：只建一次、反复用、线程退出时关闭（GDI DC 有线程亲和性，
  绝不跨线程 grab）。运行循环因此固定在一条后台线程上跑、UI 仅轮询取最近帧。
- 节点调度本身是微秒级 Python 调用，相对截图/OCR/匹配可忽略。

## 2. 核心抽象（`flow/core/`）

| 模块 | 内容 |
|---|---|
| `types.py` | `Port`（端口：exec/data × 数据类型）、`ParamSpec`（声明式参数，驱动 UI 与序列化） |
| `node.py` | `Node` / `DataNode`（实现 `evaluate`）/ `ControlNode`（实现 `execute`）+ 注册表 |
| `graph.py` | `Graph`：节点实例 + exec/data 连线 + JSON 序列化 |
| `context.py` | `ExecutionContext`：截图/OCR/按键/取色/输入屏蔽/锁/修饰键检测/黑板变量/记忆缓存/dry_run |
| `executor.py` | `Executor`：执行流遍历 + 数据流惰性拉取 + 每帧兜底清理 + headless 主循环 |

- **参数 Schema 化**：节点用 `ParamSpec` 声明参数（类型含 `region/point/color/template/templates/key/keys/int/float/bool/enum/str/regex`），
  编辑器据此**自动生成配置控件**，无需手写配置界面；区域/坐标/模板/快捷键等原 `config.py` 的配置随之迁入各节点。
- **dry_run**：操作类节点在 `ctx.dry_run` 时只记日志、不真正发按键，便于无游戏环境端到端验证。

## 3. 节点目录（`flow/nodes/`，共 39 个；调色板按 category 分组）

- **basic**：`event.on_tick` / `data.const_number` / `data.switch` / `data.get_var` / `control.set_var`
  / `logic.compare|and|or|not` / `math.arith|min|clamp` / `control.if`（分支，按是/否分岔执行流，对应蓝图 Branch） / `debug.log`
  / `data.extract_numbers`（从文本按正则抠出数字列表）/ `data.list_get`（列表取第 N 个）/ `data.list_aggregate`（列表求和/平均/最值/计数/取首尾）
- **sense**：`sense.capture`（截图）/ `sense.pixel_color` / `sense.window_check`
  / `sense.template_match`（单/多模板，可选 `transition_guard` 半透明UI抑制）
  / `sense.ocr_text`（通用 OCR 文本）/ `sense.ocr_number`（识别数字：字符纠正 + 数字列表 + 便捷首/次值）
  / `sense.modifier_down`（修饰键检测，输出"按住修饰键"是/否；接「分支」即"按住则暂停"）
- **game**：`game.occlusion`（三态遮挡，自带跨帧状态机）
  / `game.building_count`（选中建筑计数，原「多TC计数」；单建筑预检测 + 数字模板滑动匹配 + 按键后自动重试重截）
  / `game.produce_count`（产能 = min 链，支持食物/木头/黄金/石头四资源逐段扣减结转）
- **action**：`action.press_key`（可附带修饰键/重复 N 次，「数量」可连入）/ `action.release_modifiers` / `action.mouse_click`
- **control**：`control.every`（定时门）/ `control.prefetch_data`（预读：把识别耗时挪出输入屏蔽窗口）
  / `control.prefetch_full`（整屏预取，默认不用）/ `control.input_block_begin|end` / `control.lock_acquire|release`
  / `control.delay` / `control.set_switch`（运行时把另一个开关节点设开/关，如「没市场就关掉出商人」）
  （注：无"结束本帧"节点——执行流走到没有连出的出口即结束本帧）

## 4. 流程图 JSON 格式

```json
{
  "version": 1,
  "name": "普通出农",
  "nodes": [{"id": "tick", "type": "event.on_tick", "pos": [x, y], "params": {"interval": 0.1}}],
  "exec_edges": [["src_id", "src_port", "dst_id", "dst_port"]],
  "data_edges": [["src_id", "src_out_port", "dst_id", "dst_in_port"]]
}
```

> 顶层还可带若干**仅编辑器展示、不参与执行**的键：`description`（流程说明）、`panel`（控制面板置顶参数）、
> `groups`（可视化分组/子图框）、`notes`（节点说明）、`labels`（参数自定义显示名）、`foldparams`/`groupexpose`
> （逐级暴露参数）、`overlaypanel`（游戏内覆盖层显示的开关子集）。详见 `flow/core/graph.py`。

内置默认流程只有一个：`flows/combined.flow.json`（**统一生产**：同图依次出 村民/乡骑/商人，各段独立开关，
默认只开村民）。它由 `flow/flows/combined.py` 构建、`python selfcheck.py` 自动排版后落盘。
`flow/flows/` 下的 `villager.py` / `trade_cart.py` / `jin.py` 现仅作引擎逻辑的单元测试用例，不再作为内置流程分发。

## 5. 如何新增一个节点

在 `flow/nodes/` 某模块中：

```python
@register
class MyNode(DataNode):          # 或 ControlNode
    type_id = "sense.my_thing"   # 全局唯一
    category = "感知"
    title = "我的节点"
    inputs = [data_in("image", DataType.IMAGE)]
    outputs = [data_out("value", DataType.NUMBER)]
    params = [ParamSpec("threshold", "阈值", "float", default=0.5)]

    def evaluate(self, ctx, inputs):     # ControlNode 则实现 execute -> (outputs, 下一执行出口)
        ...
        return {"value": ...}
```

确保该模块被 `flow/nodes/__init__.py` 导入即可注册。编辑器会自动出现在调色板里、参数自动生成控件。

## 6. 如何新增一个流程

- 简单变体：复用 `flow/flows/_common.build_single_type(cfg)`，改 `cfg` 即可（见 `trade_cart.py`）。
- 复杂逻辑：参照 `jin.py`（多模板占用、优先级回退、每类型独立参数）或 `combined.py`
  （多段共享人口/资源池、逐段扣减结转、生产门控前置短路）直接搭图。
- 最终用户应通过**可视化编辑器**搭建/修改流程；Python 构建器主要用于内置默认模板与测试。

## 7. 开发环境与验证

编辑器是 **LiteGraph.js + pywebview**（Windows 下用系统 WebView2 渲染）。Python 3.14（及更低）均可。

```bash
pip install -r requirements.txt
python run_editor.py [flow.json]                # 打开网页节点编辑器（缩放/右键菜单/节点内参数/采集工具）
python check_web.py                             # 编辑器宿主无头冒烟（节点定义导出 + 图↔载荷往返）
python selfcheck.py                             # 引擎 + 流程 dry-run（不需游戏/cv2/OCR/按键）
python run_headless.py --dry-run                # 在游戏中演练：只打印不发按键
python run_headless.py                          # 在游戏中实际运行（输入屏蔽需管理员）
```

诊断：设环境变量 `AOE4_EDITOR_DEBUG=1` 可在网页编辑器中打开 WebView2 开发者工具。

`python selfcheck.py` —— 不依赖游戏/cv2/OCR/真实按键：用桩替换感知节点，在 dry_run 下端到端
验证四个流程（出农/出商人/金朝/统一生产）的分支、产能计算、操作时序与锁/屏蔽兜底，并校验
JSON 序列化往返与自动排版无重叠。

`python check_web.py` —— 不需 pywebview/界面：只测可单元化的转换核心（`node_defs` 导出、
`graph_to_payload`/`payload_to_graph` 往返、参数类型回解析）。

`python run_headless.py [--dry-run] [--file ...]` —— 加载流程图在真实游戏中运行（实际运行等价于旧 main.py）。

  参数控件、拖拽连线并校验 执行↔执行/数据↔数据、删除/复制/分组/折叠子图、打开/保存 JSON。
