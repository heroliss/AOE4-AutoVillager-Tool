# 节点式自动化引擎 —— 架构与开发指南

本项目正从"写死的出农脚本"重构为**节点式可视化自动化引擎**：把"检测 → 判断 → 操作"
的流程拆成可在画布上自由连线的节点图，以支持出农、市场出商队、金朝双出农等多种场景，
未来新需求多数只需改连线/改参数，少数加一个小节点即可。

> 旧的 `main.py` / `gui_app.py` / 各 `*_reader.py` 暂保留，其算法作为节点内部实现被复用，
> 待编辑器成熟后再行清理。

## 1. 执行模型：执行流 + 数据流（类 Blueprint）

- **执行流（exec）**：白色实线，决定"先做什么、再做什么"。入口是 `event.on_tick`，
  沿执行线逐个访问控制节点。「分支」(`control.if`) 等节点有多个执行出口（如 真/假），以此实现分支
  与"跳过本轮"；出口不接任何节点即"本帧到此结束"（无专门的结束节点）。
- **数据流（data）**：彩色线，**惰性传值**。当某节点需要一个输入值时，才向上游"拉取"，
  且结果**按帧记忆化**（同一帧内每个节点输出只算一次）。
- 一帧（tick）结束后，执行器**兜底释放**可能持有的输入屏蔽与文件锁，避免跨帧泄漏。

与旧主循环的对应：`修饰键暂停 → 窗口检测 → 队列检测(不满足则跳过本轮) → OCR → 条件 → 操作`
逐条映射为节点与执行线分支。

### 性能要点

- **按帧记忆化** + `整屏预取` 节点：在慢路径开头放一个 `control.prefetch_full`，整屏只截一次，
  其后所有 `sense.capture` / 模板匹配 / OCR 直接从整屏缓存**切片复用**，避免多次截图。
  快路径（每帧只看队列那一小条）则仍用小区域截图，更省。用哪种由连线决定。
- 重型识别（OCR）只在被取到的执行路径**实际需要时**才求值。
- 保留旧的微优化：`GetPixel` 取像素（<0.1ms，绕过截图）、灰度模板匹配、模板缓存、
  mss 每线程实例、`control.every` 定时门限频。
- 节点调度本身是微秒级 Python 调用，相对截图/OCR/匹配可忽略。

## 2. 核心抽象（`flow/core/`）

| 模块 | 内容 |
|---|---|
| `types.py` | `Port`（端口：exec/data × 数据类型）、`ParamSpec`（声明式参数，驱动 UI 与序列化） |
| `node.py` | `Node` / `DataNode`（实现 `evaluate`）/ `ControlNode`（实现 `execute`）+ 注册表 |
| `graph.py` | `Graph`：节点实例 + exec/data 连线 + JSON 序列化 |
| `context.py` | `ExecutionContext`：截图/OCR/按键/取色/输入屏蔽/锁/修饰键检测/黑板变量/记忆缓存/dry_run |
| `executor.py` | `Executor`：执行流遍历 + 数据流惰性拉取 + 每帧兜底清理 + headless 主循环 |

- **参数 Schema 化**：节点用 `ParamSpec` 声明参数（类型含 `region/point/color/template/templates/key/keys/int/float/bool/enum/str/regex`），
  编辑器据此**自动生成配置控件**，无需手写配置界面；区域/坐标/模板/快捷键等原 `config.py` 的配置随之迁入各节点。
- **dry_run**：操作类节点在 `ctx.dry_run` 时只记日志、不真正发按键，便于无游戏环境端到端验证。

## 3. 节点目录（`flow/nodes/`，共约 34 个）

- **basic**：`event.on_tick` / `data.const_number` / `data.switch` / `data.get_var` / `control.set_var`
  / `logic.compare|and|or|not` / `math.arith|min|clamp` / `control.if`（分支，按是/否分岔执行流，对应蓝图 Branch） / `debug.log`
- **sense**：`sense.capture`（截图）/ `sense.pixel_color` / `sense.window_check`
  / `sense.template_match`（单/多模板，可选 `transition_guard` 半透明UI抑制）/ `sense.ocr_number`（首个/两组/求和）
  / `sense.modifier_down`（修饰键检测，输出"按住修饰键"是/否；接「分支」即"按住则暂停"）
- **game**：`game.occlusion`（三态遮挡，自带跨帧状态机）/ `game.tc_count`（多TC单次检测）/ `game.produce_count`（产能 = min 链）
- **action**：`action.press_key`（修饰键/重复/Shift批量/结束ESC）/ `action.release_modifiers` / `action.mouse_click`
- **control**：`control.prefetch_full`（整屏预取）/ `control.every`（定时门）
  / `control.input_block_begin|end` / `control.lock_acquire|release` / `control.delay`
  （注：无"结束本帧"节点——执行流走到没有连出的出口即结束本帧）

## 4. 流程图 JSON 格式

```json
{
  "version": 1,
  "name": "普通出农",
  "nodes": [{"id": "tick", "type": "event.on_tick", "pos": [x, y], "params": {"interval": 0.1}}],
  "exec_edges": [["src_id", "src_port", "dst_id", "dst_port"]],
  "data_edges": [["src_id", "src_out_port", "dst_id", "dst_in_port"]]
}
```

内置三个默认流程：`flows/villager.flow.json`、`flows/trade_cart.flow.json`、`flows/jin.flow.json`
（由 `flow/flows/` 下的构建器生成，`python selfcheck.py` 会重新落盘）。

## 5. 如何新增一个节点

在 `flow/nodes/` 某模块中：

```python
@register
class MyNode(DataNode):          # 或 ControlNode
    type_id = "sense.my_thing"   # 全局唯一
    category = "感知"
    title = "我的节点"
    inputs = [data_in("image", DataType.IMAGE)]
    outputs = [data_out("value", DataType.NUMBER)]
    params = [ParamSpec("threshold", "阈值", "float", default=0.5)]

    def evaluate(self, ctx, inputs):     # ControlNode 则实现 execute -> (outputs, 下一执行出口)
        ...
        return {"value": ...}
```

确保该模块被 `flow/nodes/__init__.py` 导入即可注册。编辑器会自动出现在调色板里、参数自动生成控件。

## 6. 如何新增一个流程

- 简单变体：复用 `flow/flows/_common.build_single_type(cfg)`，改 `cfg` 即可（见 `trade_cart.py`）。
- 复杂逻辑：参照 `jin.py` 直接搭图（多模板占用、优先级回退、每类型独立参数）。
- 最终用户应通过**可视化编辑器**搭建/修改流程（Phase 1 起），Python 构建器主要用于内置默认模板与测试。

## 7. 开发环境与验证

Python 3.14（及更低）均可，DearPyGui 已在 3.14 验证可用：

```bash
pip install -r requirements.txt
python run_editor.py flows\villager.flow.json   # 打开编辑器（构图/连线/参数/存读）
python check_editor.py                          # 编辑器无头冒烟
python selfcheck.py                             # 引擎+三流程 dry-run（不需游戏）
python run_headless.py --dry-run                # 在游戏中演练：只打印不发按键
python run_headless.py                          # 在游戏中实际运行（输入屏蔽需管理员）
```


`python selfcheck.py` —— 不依赖游戏/cv2/OCR/真实按键：用桩替换感知节点，在 dry_run 下端到端
验证三个流程的分支、产能计算、操作时序与锁/屏蔽兜底，并校验 JSON 序列化往返。

`python run_headless.py [--dry-run] [--file ...]` —— 加载流程图在真实游戏中运行（实际运行等价于旧 main.py）。
